# Аннотация

**Задача.** Требуется прогнозировать среднедушевые безналичные расходы жителей муниципальных образований (МО) по шести категориям на 1, 3, 6 и 12 месяцев вперёд точнее базовой модели Prophet и как можно раньше обнаруживать шоки, то есть резкие структурные изменения расходов.

**Метод прогноза.** Финальная модель представляет собой ансамбль из 11 членов с равными весами в логарифмах: 9 вариантов предложенной модели STF (Seasonality Transfer Forecaster, перенос сезонности) и две foundation-модели, Chronos-2 и TimesFM 2.5. STF компенсирует короткую историю рядов, перенося сезонный профиль с групп похожих рядов и с национальных рядов СберИндекса. Foundation-модели получают ряд с удлинённым контекстом, построенным по национальному ряду СберИндекса.

**Результат прогноза.** Модель проверена на всех 12 096 полных рядах (2 016 МО × 6 категорий) в трёх режимах оценки. Она точнее Prophet на всех горизонтах во всех режимах, причём как Prophet с настройками по умолчанию, так и настроенного. В основном режиме финальная модель точнее Prophet во всех 24 ячейках «категория × горизонт».

# 1. Постановка задачи

## 1.1 Объект прогноза

Единица прогноза: ряд «МО × категория», то есть средние безналичные расходы одного жителя МО за месяц в рублях. Рассматриваются шесть категорий: «Все категории», «Продовольствие», «Маркетплейсы», «Общественное питание», «Транспорт», «Здоровье». Данные охватывают 24 месяца, с января 2023 г. по декабрь 2024 г. Горизонты прогноза: 1, 3, 6 и 12 месяцев.

Организаторы оставили выбор категорий, МО и параметров участникам. Я прогнозирую все категории и все МО. Основная оценка ведётся на 12 096 полных рядах (24 месяца без пропусков). Неполные ряды тоже прогнозируются, но в сравнение не входят, так как у части из них нет даже 12 месяцев истории.

## 1.2 Определение шока

Шоком называется резкое изменение расходов, необычное для данного МО и не объяснимое сезонностью, общим трендом и общероссийскими событиями месяца. Формально шок соответствует большому остатку прогноза на один месяц после вычитания общего для категории эффекта месяца (раздел 5.1). Рассматриваются четыре формы шока: сдвиг уровня, временный провал, плавный сдвиг и разовый всплеск.

## 1.3 Основная трудность и идея решения

История рядов коротка. В первой точке прогноза (декабрь 2023 г.) у каждого ряда есть только 12 месяцев, то есть одно наблюдение на каждый месяц года. По одному году ни Prophet, ни ARIMA, ни ETS не могут надёжно оценить годовую сезонность. Поэтому центральная идея решения состоит в переносе сезонности из более длинных или более массовых источников: из похожих рядов той же категории и региона и из национальных рядов СберИндекса, которые начинаются в 2018 г.

## 1.4 Обоснование выбора подходов

Часть методов в решении не является стандартной для прогноза расходов, поэтому для каждого компонента ниже указано, какую проблему он решает и почему выбран именно он.

| компонент | почему выбран |
|---|---|
| STF, перенос сезонности | По 12-24 точкам сезонность отдельного ряда не оценивается. В панели тысячи рядов с похожей сезонностью внутри категории и региона, а национальные ряды СберИндекса содержат её с 2018 г. Иерархическое сжатие профиля (категория, регион, МО) даёт устойчивую оценку группы и добавляет собственные особенности ряда с малым весом. |
| затухающий рост | Текущий рост расходов, особенно у маркетплейсов, не сохраняется бесконечно. Затухание тренда (Gardner, McKenzie, 1985) является проверенным способом избежать линейной экстраполяции на длинных горизонтах. |
| ансамбль с равными весами | При коротком периоде проверки оценённые веса ненадёжны, а простое среднее устойчивее (Smith, Wallis, 2009). |
| Chronos-2 и TimesFM 2.5 | Современные предобученные модели временных рядов работают без обучения на коротком ряду (zero-shot) и отвечают требованию конкурса об использовании фундаментальных моделей. Две модели разной архитектуры выбраны, чтобы их ошибки были слабее связаны. Режим extended даёт им длинный контекст, к которому они привыкли при обучении. |
| AutoETS, AutoTheta, AutoARIMA | Стандартные классические эталоны с автоматическим подбором параметров. Theta выиграла соревнование M3 (Makridakis, Hibon, 2000). Они показывают, что выигрыш финальной модели не сводится к слабости одного Prophet. |
| панельный и региональный детекторы | Используют структуру данных: МО сравнивается с соседями по региону в том же месяце, что убирает общие сезонные и региональные эффекты. Региональный уровень закрывает слепую зону панельного детектора. |
| BOCPD | Байесовский онлайн-детектор оценивает вероятность смены режима в каждом месяце, работает в реальном времени без использования будущих данных и не требует заранее знать число точек изменения. |
| CUSUM, Page-Hinkley, PELT, BinSeg | Классические методы обнаружения точек изменения, включены как эталоны для сравнения. |
| Qwen2.5-7B-Instruct (AWQ) | Открытая модель с хорошим качеством на русском языке. В 4-битной квантизации помещается в одну GPU NVIDIA T4 и запускается локально через vLLM, без передачи данных во внешние сервисы. Ответ строго по JSON-схеме делает разметку воспроизводимой. |
| выбор МО из справочника | Гарантирует, что каждая привязка новости существует в данных СберИндекса; согласование новостей с данными является отдельным критерием конкурса. |
| кластерный бутстреп по МО | Ошибки одного МО по категориям и месяцам связаны между собой, и обычный бутстреп занизил бы ширину доверительного интервала. |
| R² годового прироста и MASE | R² уровня почти всегда близок к 0,99 и не различает модели. R² прироста измеряет точность динамики, MASE позволяет сравнивать ряды разного масштаба. |

# 3. Схема оценки

## 3.1 Режимы оценки

Все модели оцениваются на одном и том же наборе из 12 096 полных рядов в трёх режимах.

1. **Скользящая точка прогноза (основной режим).** Модель строит прогноз из каждого месяца T = 2023-12, 2024-01, …, 2024-11 на месяц T + h, используя данные до T включительно. Для h = 1 получается 12 точек прогноза, для h = 3 десять, для h = 6 семь, для h = 12 одна (T = 2023-12). Всего 362 880 прогнозов на модель. Это наиболее статистически надёжный режим.
2. **Одна точка прогноза T = 2024-12 - h.** Классическая отложенная выборка из последних h месяцев. В таком режиме обычно проводят сравнение с Prophet.
3. **Целевые месяцы с июля по декабрь 2024 г.** Все прогнозы, попадающие во второе полугодие 2024 г. (далее H2).

## 3.2 Метрики

Обозначим через y фактическое значение и через ŷ прогноз. Усреднение ведётся по всем рядам и точкам прогноза при данном горизонте h.

- **MAE** = среднее |y - ŷ|, руб. на жителя в месяц. Основная метрика по условиям конкурса.
- **R² уровня.** Требуется условиями, однако в этой задаче почти всегда близок к 0,99: МО сильно различаются по уровню расходов, и даже прогноз «как в прошлом месяце» получает высокий R². Поэтому дополнительно считается **R² годового прироста**, то есть R² между фактическим и прогнозным приростом g = y<sub>t</sub> / y<sub>t-12</sub> - 1. Эта метрика показывает, предсказывает ли модель динамику, а не только уровень.
- **MAPE**, %.
- **MASE** (Hyndman, Koehler, 2006): отношение абсолютной ошибки к средней величине |y<sub>t</sub> - y<sub>t-1</sub>| ряда на обучающем отрезке. Значение меньше 1 означает, что модель точнее наивного прогноза «как в прошлом месяце» внутри выборки.
- **Доля рядов**, на которых модель точнее Prophet.
- **95 % доверительный интервал разности MAE**: кластерный бутстреп по МО, 1 000 повторов (Cameron и др., 2008). Ошибки одного МО по разным категориям и месяцам зависимы, поэтому при повторной выборке МО берутся целиком.

## 3.3 Фиксация гиперпараметров

Гиперпараметры зафиксированы в `configs/models.yaml` до оценки. Веса ансамбля равные и на тестовом периоде не подбирались. Решения, которые всё же принимались по результатам бэктеста, и связанные с ними оговорки перечислены в разделе 7.

# 4. Прогноз потребления

## 4.1 Сравниваемые модели

- **Prophet** (Taylor, Letham, 2018), базовая модель организаторов. Код организаторов не опубликован, поэтому рассчитаны два варианта. Prophet по умолчанию: `Prophet()` на месячных данных, отдельно для каждого ряда. Настроенный Prophet: мультипликативная сезонность, `yearly_seasonality=3`, `changepoint_prior_scale=0.01`. Оба варианта рассчитаны на всех рядах и во всех точках прогноза. Основное сравнение ведётся с Prophet по умолчанию, поскольку базовую модель обычно задают именно так. Настроенный Prophet точнее варианта по умолчанию в режиме одной точки и на целевых месяцах H2 при h от 1 до 6, но хуже в скользящем режиме и значительно хуже при h = 12. Финальная модель точнее обоих вариантов во всех режимах (раздел 4.4).
- **Наивные модели**: последнее значение; сезонная наивная модель (значение 12 месяцев назад); сезонная наивная модель с поправкой на годовой рост.
- **Классические статистические модели** из библиотеки statsforecast: AutoETS (Hyndman и др., 2008), AutoTheta (Assimakopoulos, Nikolopoulos, 2000), AutoARIMA (Hyndman, Khandakar, 2008). Каждая рассчитана в двух режимах: на исходном ряду с сезонностью 12 и на ряду, очищенном от сезонности STF.
- **Foundation-модели** без дообучения (zero-shot): Chronos-2 (Ansari и др., 2025) и TimesFM 2.5 (Das и др., 2024), каждая в трёх режимах подачи данных (раздел 4.3). Модель TiRex (NX-AI) также пробовалась, но её запуск завершился ошибкой при разборе выходных данных, и в сравнение она не вошла.
- **STF и ансамбль**, описанные ниже.

## 4.2 Модель STF

Прогноз STF строится в логарифмах как произведение трёх компонент:

> ŷ<sub>T+h</sub> = L<sub>T</sub> · G<sub>T,h</sub> · S<sub>m(T+h)</sub>,

где L<sub>T</sub> обозначает текущий уровень ряда, G<sub>T,h</sub> рост за h месяцев, S<sub>m</sub> сезонный множитель целевого месяца m.

1. **Уровень** L<sub>T</sub>: среднее двух последних значений ряда, очищенных от сезонности и приведённых к моменту T.
2. **Рост** G<sub>T,h</sub>. Годовой прирост категории оценивается как медиана прироста по всем МО панели за последние 1, 3 или 6 месяцев. Если у панели ещё нет года истории, используется национальный ряд СберИндекса. Для маркетплейсов, здоровья и транспорта, у которых нет месячного национального аналога, используется недельный ряд СберИндекса по соответствующей категории. Прирост региона учитывается частично: G<sub>регион</sub> = G<sub>категория</sub> · (G<sub>медиана региона</sub> / G<sub>категория</sub>)<sup>0,5</sup>.
   Текущий быстрый рост (например, у маркетплейсов от +50 до +70 % г/г) не может сохраняться бесконечно, поэтому месячный темп роста с каждым шагом стягивается к долгосрочному темпу национального ряда a, равному среднему приросту за 3 года до T: g<sub>h</sub> = a + (g - a)·φ<sup>h</sup>, где φ от 0,8 до 0,95 задаёт скорость затухания. Вместе с учётом регионального роста затухание уменьшило MAE при h = 6 и h = 12 на 51 и 43 руб. (раздел 7.2).
3. **Сезонность** S<sub>m</sub>: сезонный профиль ряда, сжатый к профилю группы по иерархии «категория, регион, МО». Медианный профиль категории по стране надёжен, так как опирается на тысячи рядов. Профиль региона входит с весом λ = 0,5, собственный профиль МО с весом λ = 0,3. Благодаря этому МО с одним годом истории получает устойчивую сезонность от похожих рядов и сохраняет собственные особенности, например более сильный летний пик в курортных МО.

**Ансамбль STF** состоит из 9 вариантов: φ ∈ {0,8; 0,9; 0,95} × окно оценки роста {1, 3, 6} мес. Прогнозы усредняются в логарифмах с равными весами. Короткое окно быстрее реагирует на изменения, длинное устойчивее к шуму. В бэктесте один из вариантов (φ = 0,8, окно 1 мес.: 310 / 417 / 443 / 521) оказался точнее среднего девяти (319 / 434 / 462 / 524), однако это можно установить только задним числом. Выбор варианта по тестовому периоду был бы подгонкой, а равные веса защищают от неудачного выбора. Это согласуется с известным эффектом комбинирования прогнозов: простое среднее обычно надёжнее оценённых весов (Smith, Wallis, 2009).

**Финальная модель** вычисляется как среднее логарифмов прогнозов 11 членов с равными весами: 9 вариантов STF, Chronos-2 extended и TimesFM 2.5 extended.

# 5. Обнаружение шоков

## 5.1 От остатка прогноза к тревоге

1. **Остаток прогноза на один месяц**: e<sub>t</sub> = log y<sub>t</sub> - log ŷ<sub>t|t-1</sub>, где ŷ<sub>t|t-1</sub> обозначает прогноз STF по данным до месяца t-1. Модель использует только прошлое, поэтому остаток измеряет неожиданность месяца t.
2. **Вычитание общего эффекта месяца.** Из остатка вычитается медиана остатков категории по всей стране в этом месяце. Без этого шага общероссийские события (праздники, календарные эффекты, изменение ставки) вызывали бы тревоги одновременно во всех МО. Отсутствие этого шага было главной ошибкой первоначальной постановки: без него CUSUM и PELT давали F1, близкий к нулю.
3. **Детектор** преобразует остатки в оценку необычности, а порог переводит оценку в тревогу. Все оценки вычисляются только по прошлому. Исключение составляют медианы по МО того же месяца, которые известны в момент принятия решения.

## 5.2 Детекторы

| детектор | принцип |
|---|---|
| panel (панельный) | остаток МО минус медиана остатков той же категории в регионе, делённый на робастный масштаб ряда; тревога, если МО отклоняется от соседей по региону |
| regional (региональный уровень) | медиана остатков категории в регионе в сравнении с историей самого региона; выявляет шок, общий для всего региона |
| panel_regional (двухуровневый) | тревога, если необычен МО относительно региона или регион относительно страны (максимум перцентильных рангов двух оценок) |
| conformal, conformal_raw | калиброванные квантили ошибки прогноза; вариант conformal_raw без вычитания общего эффекта месяца (абляция) |
| CUSUM, CUSUM с перезапуском, Page-Hinkley | накопленные отклонения (Page, 1954); вариант с перезапуском обнуляет статистику после превышения порога h = 4σ |
| BOCPD | байесовское онлайн-обнаружение точки изменения в собственной истории ряда (Adams, MacKay, 2007); оценка равна P(длина серии ≤ 1) |
| PELT, BinSeg | офлайн-сегментация (Killick и др., 2012; библиотека ruptures, Truong и др., 2020) на растущем окне без использования будущих данных |
| multivariate, panel_multivariate | одновременное отклонение нескольких категорий одного МО; во втором варианте среднее с панельной оценкой |
| panel_bocpd | максимум рангов панельного детектора и BOCPD |
| гибрид с новостями | оценка детектора × (1 + γ·[в МО в этом месяце есть происшествие тяжести не ниже 2]) |

Без гибрида с новостями получается 14 вариантов, все они рассчитываются на всех 12 096 полных рядах.

## 5.4 Реальные события

**Схема сравнения.** Детекторы дают оценку для ряда, а событие относится к МО, поэтому оценка МО-месяца равна максимуму по категориям. Бюджет тревог одинаков для всех детекторов: 10,5 % МО в каждом месяце; столько даёт панельный детектор при 2 % ряд-месяцев. У детекторов с дискретной оценкой фактическая доля меньше (у PELT и BinSeg 0,8 %). Порог по срезу месяца применим в реальном времени и не позволяет детектору выигрывать за счёт месяцев, в которых у него много тревог. Например, PELT и BinSeg при общем пороге давали почти все тревоги в мае и октябре и поэтому попадали в апрельские паводки с запаздыванием.

## 5.6 Раннее предупреждение

Шоком здесь считается тревога панельного детектора в любой категории МО, то есть местный шок. Обучение проводится на месяцах до мая 2024 г., проверка на месяцах с июня по ноябрь 2024 г.

## 6.2 Версия 1: правила, Natasha и словарь

Первая версия определяла тип события по словарю, извлекала места с помощью NER-модели Natasha с морфологическим анализом и привязывала их через газеттир. Газеттир включал 144 названия регионов, 12 582 варианта названий МО и 129 тыс. населённых пунктов ИНИД, привязанных к МО по полигонам справочника СберИндекса. Проверка 200 случайных событий показала: место верно в 80,9 % случаев, тип в 79,0 %, оба поля в 69,3 %.

Типичные ошибки: имена людей принимались за города («Владимир Путин» привязывался к г. Владимир), в выборку попадали дайджесты, сообщения о предотвращённых терактах, судебные новости, события за пределами России и информационные сообщения МЧС о спасении животных. Версия 1 отклонена, но сохранена в репозитории для сравнения.

## 6.3 Версия 2: классификация языковой моделью и выбор МО из справочника

Используется модель Qwen2.5-7B-Instruct-AWQ (Qwen Team, 2024) в движке vLLM (Kwon и др., 2023) на GPU NVIDIA T4; скорость около 1,4 сообщения в секунду на одну GPU, всего более 20 GPU-часов. Настройки одинаковы для всех каналов: на вход до 1 500 символов, на выход до 300 токенов.

- **Этап A, понимание.** Модель читает сообщение и отвечает в формате JSON по фиксированной схеме: является ли сообщение реальным происшествием, тип (14 типов), тяжесть по шкале от 0 до 3, произошло ли событие в России, места в текстовом виде (населённый пункт, район, город, регион). Инструкция явно исключает дайджесты, судебные новости, предотвращённые теракты, учения, спасение одного человека или животного и т. п.
- **Этап B, привязка к справочнику СберИндекса.** По текстовому описанию места подбираются кандидаты: нечёткое сравнение (rapidfuzz) с названиями МО и населённых пунктов внутри названного региона. Модель выбирает номер кандидата, вариант «только регион» или «не определить». Поэтому итоговый `territory_id` всегда существует в справочнике СберИндекса, и модель не может выдумать МО.
- **Правила согласования.** «Москва», «Санкт-Петербург» и «Севастополь» без указания района относятся к уровню региона: в данных СберИндекса эти города разбиты на внутригородские территории, и приписывание события одной из них было бы ошибкой. Если указан только регион, событие также относится к уровню региона.

## 6.4 От сообщения к признаку «МО × месяц»

1. **Время.** Используется дата публикации по московскому времени. Месяц события совпадает с месяцем публикации, поэтому признак месяца t известен к концу месяца t без использования будущих данных.
2. **Объединение повторов в происшествия.** Сообщения об одном месте и одном типе с интервалом не более 3 дней в пределах одного месяца считаются одним происшествием. Тяжесть происшествия равна максимуму по его сообщениям, громкость равна числу сообщений. Цепочка обрывается на границе месяца: признак месяца t строится только из сообщений месяца t, а длительная ситуация (например, регулярные атаки БПЛА на регион) учитывается в каждом месяце, когда о ней сообщают. Так, 192 сообщения о паводке в Орске объединяются в одно происшествие тяжести 3. В итоге 33 159 сообщений о событиях образуют 11 858 происшествий (сжатие в 2,8 раза).
3. **Признаки «МО × месяц»**: число происшествий по группам (безопасность, бедствия, инфраструктура, прочее), сумма и максимум тяжести, громкость, всплеск относительно среднего за предыдущие 12 месяцев. Аналогичные признаки строятся на уровне региона; в них входят события, привязанные к региону или к любому его МО.
4. **Привязка к МО панели** выполняется по `territory_id` справочника СберИндекса с учётом версий МО 2022-2024 гг. и объединений. События в восьми регионах без данных СберИндекса в панель не попадают, но сохраняются для объяснения.

- **Объяснение тревог.** К каждой тревоге «МО × месяц» прилагаются происшествия этого МО и региона: тип, тяжесть, число сообщений, каналы. Крупное происшествие найдено у 10 из 2 541 тревог, то есть новости объясняют отдельные крупные шоки, а не большинство тревог.
- **Прогноз.** Новостные признаки не уменьшили MAE (раздел 7.3), поскольку шоки редки и общая ошибка определяется обычными месяцами.

## 7.3 Отклонённые подходы

Числа взяты из рабочих экспериментов на момент попытки; базовая версия STF тогда могла отличаться от финальной.

- **LightGBM поверх STF** с внешними признаками (новости, погода, ИПЦ, ставка, доходы). Первая версия обучалась на ранних точках и проигрывала из-за сдвига распределения (h = 6: 724). Вторая выучила общие для месяца ошибки (h = 1: 504). Третья, с целевой переменной, очищенной от общего эффекта месяца, дала результат на уровне STF (-3 % при h = 1), но поверх ансамбля с затуханием ухудшила прогноз (342 / 463 / 492 / 605). Подход отклонён: внешние признаки не уменьшают общую MAE, поскольку шоки редки.
- **Собственный тренд МО** по одному году истории: при h = 12 ошибка выросла с 650 до 750. Отклонён, так как по одному году тренд неотличим от шума.
- **Нормировка на число дней в месяце** (високосный февраль 2024 г.): 352 / 500 / 562 / 653, хуже. Отклонена.
- **Медианный уровень вместо среднего**: 362 / 492 / 551 / 662, хуже. Отклонён.
- **Веса ансамбля по прошлым ошибкам** (три лучших члена, веса пропорциональны 1/MAE²): не лучше равных весов. Отклонены.
- **Отказ от затухания для категорий без прямого национального аналога**: лучше при h = 12, хуже при h от 3 до 6. Отклонён. Проверка на 2025 г. показала, что для маркетплейсов затухание действительно оказалось слишком сильным (раздел 4.7).
- **Поправка уровня после тревоги** (частичный откат шока): ошибка рядов с тревогой выросла с 338 до 365. Отклонена: шоки в расходах в среднем устойчивы и ведут себя как сдвиг уровня.
- **Настроенный Prophet** (мультипликативная сезонность, мягкий тренд): хуже Prophet по умолчанию при h = 12 (2 478).
- **Foundation-модели на исходном ряду**: 660 / 898 / 1 301 / 2 805 (Chronos-2), хуже Prophet. Это привело к разработке режимов stf_resid и extended (раздел 4.3).
- **ETS, Theta и ARIMA** на исходном и на очищенном от сезонности ряду приведены в таблицах раздела 4.4. В основном режиме ни одна классическая модель не превосходит ансамбль STF; в узких срезах Theta на очищенном ряду иногда точнее.

## 7.4 Контроль качества и исправленные ошибки

Перед сдачей решение дважды проверено независимым пересчётом. MAE во всех режимах, R², проверка 2025 г., точность новостей и данные лендинга пересчитаны отдельным кодом, не использующим функции проекта, и совпали с результатами. STF дополнительно перезапущена на данных, обрезанных по точке прогноза, и дала идентичный результат, то есть утечки в STF нет. Вторая проверка охватила все компоненты на предмет утечки и все числа в тексте; её замечания учтены в этой версии отчёта.

Проверка выявила одну утечку, в режиме extended у foundation-моделей: сезонный профиль национального ряда для синтетической предыстории вычислялся по всему ряду до августа 2026 г. и без удаления тренда. ## 7.5 Детекция

Сначала все детекторы работали на исходных остатках, и CUSUM и PELT давали F1, близкий к нулю. Анализ выявил три ошибки постановки. (1) В остатках есть общий для страны компонент месяца, поэтому из остатков вычитается медиана категории по месяцу (после этого F1 у CUSUM 0,19, у PELT 0,26). (2) PELT и BinSeg давали бинарную оценку, и порог нельзя было откалибровать; оценка заменена непрерывной (максимальный штраф, при котором точка изменения ещё обнаруживается). (3) На первых месяцах масштаб остатков оценивался как нулевой; введены минимум 4 точки и нижняя граница масштаба. Первая версия сравнения показала лучший результат у панельного детектора: F1 0,64 на полусинтетике, 3 из 8 событий реестра.

Затем я устранил слабые места этого сравнения:

- добавлен классический вариант CUSUM с перезапуском (F1 вырос с 0,19 до 0,52);
- медленные детекторы (BOCPD, PELT, BinSeg) считались на 12 % рядов, теперь на всех;
- на реальных событиях проверялись только 4 детектора, теперь все 14;
- бюджет тревог на уровне МО различался между детекторами, теперь он одинаков и задаётся отдельно в каждом месяце;
- полусинтетика содержала только местные шоки; добавлен сценарий региональных шоков, который выявил слепую зону панельного детектора;
- нормировка в panel_multivariate использовала будущие данные, теперь она причинная.

После этих изменений лучшим по сумме проверок стал BOCPD, а панельный детектор остался лучшим только на местных синтетических шоках (раздел 5.5).

Пробный запуск версии 2 на тех же 200 сообщениях дал 81 % верных выданных событий. # 8. Интерпретация и ограничения

- Для точного прогноза расходов МО по короткой истории необходимы три элемента: заимствованная сезонность (категории, региона, страны), аккуратная модель роста с затуханием и устойчивость за счёт ансамбля. Сложная индивидуальная модель на 24 точках проигрывает.
- Foundation-модели полезны как члены ансамбля при условии подготовки данных. Применённые к исходному короткому ряду, они уступают Prophet.
- Шоки в среднедушевых безналичных расходах МО редки и в основном происходят в небольших МО. События в крупных городах растворяются в среднем по городу.

**Ограничения:**

- нет данных по восьми приграничным регионам;
- бэктест охватывает только 2024 г., при h = 12 доступна одна точка прогноза;
- на уровне МО прогноз 2025 г. проверен только в агрегате;
- эталонные метки новостей в проверочной выборке в основном поставлены LLM-ассистентом, согласие с ручной разметкой проверено на 16 строках;
- полнота версии 2 составляет 84 % относительно верных событий версии 1;
- интервалы прогноза при h ≥ 3 узковаты;
- при общем пороге тревоги детектора концентрируются в январе, поэтому рекомендуется порог по месяцу (раздел 5.4);
- реальных событий для проверки детекторов мало (8 и 49), различия между лучшими детекторами на них статистически не значимы;
- в анализе раннего предупреждения и ошибок в месяцы шоков шок определён панельным детектором (местный шок);
- классические модели и foundation-модели в режимах raw и stf_resid рассчитаны без недельных категорий.

# 9. Воспроизводимость

```bash
pip install -r requirements.txt   # Python 3.12 или 3.13
bash run_all.sh                   # все таблицы, графики, лендинг и отчёт без GPU, около 1-1,5 ч на 2 ядрах
FULL=1 bash run_all.sh            # дополнительно пересчитать шаги, которым нужен GPU
```

- **Окружение.** Python 3.12 или 3.13. В `requirements.txt` закреплены точные версии всех пакетов, включая зависимости, на которых получены результаты. Для пересчёта Prophet и foundation-моделей нужны пакеты из `requirements-gpu.txt`. Разметка новостей языковой моделью выполняется в отдельном окружении из `requirements-llm.txt`, поскольку vllm 0.31 несовместим с версией numpy основного расчёта.
- **Конфигурации:** `configs/models.yaml` (STF, ансамбль, Prophet, LightGBM), `configs/changepoint.yaml` (детекторы, полусинтетика), `configs/news_llm.yaml` (языковая модель, фильтр).
- **Долгие шаги** (Prophet, foundation-модели, ARIMA, разметка новостей) по умолчанию не перезапускаются: их результаты хранятся в `results/` и `data/processed/llm_full/`, поэтому `run_all.sh` без GPU воспроизводит все таблицы отчёта. Режим `FULL=1` пересчитывает и их.
- **Случайность** зафиксирована: полусинтетика seed 7, бутстреп seed 0, LightGBM seed 0.
- **Отчёт** пересобирается командой `python scripts/render_report.py`, таблицы берутся из `results/*.csv`.
- **Проверка.** Публичная копия репозитория прогнана целиком в чистом окружении с версиями из `requirements.txt`: все таблицы `results/*.csv`, прогнозы бэктеста и текст отчёта совпали с исходным расчётом.
